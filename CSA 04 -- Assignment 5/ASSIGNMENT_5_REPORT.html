PART A – DESIGN (25 marks)

Linux is a modular monolithic kernel. The kernel manages processes, virtual memory, VFS/files, drivers, interrupts/DMA and networking. /etc stores configuration, /home user files, /var logs/state, /usr programs, /dev device nodes, /proc and /sys virtual runtime interfaces. CFS historically uses virtual runtime; newer kernels transition toward EEVDF. Use non-login service accounts, systemd/Gunicorn as non-root, journald, Nginx TLS reverse proxy, default-deny firewall, key-based SSH and automated backups. Ansible improves repeatability across multiple servers.

A3 – Virtualisation (5 marks)

Type-1 hypervisors run on hardware; type-2 hypervisors run as host applications. Full virtualisation presents virtual hardware; paravirtualisation uses guest-aware hypercalls. VMs isolate guest kernels and support snapshots/migration but consume guest RAM/disk and add boot/patch overhead. KVM is suitable for Linux production; VirtualBox is useful for development/test labs.

A4 – Containerisation (4 marks)

Namespaces isolate PID, mount, network, IPC, user and hostname views; cgroups account for and limit CPU, memory, I/O and process counts. Containers share the host kernel, start quickly and use fewer resources; VMs boot a guest kernel and provide a stronger kernel boundary. Use containers for stateless portal/LMS services and VMs for workloads needing a separate kernel.

A5 – Cloud and Kubernetes (4 marks)

IaaS supplies VMs/network/storage, PaaS manages runtime/platform and SaaS is a finished application. Recommend hybrid deployment: private baseline, public-cloud Kubernetes for burst replicas, load balancer/WAF, managed HA database, object storage and CDN. Pods are deployable units; Deployments maintain replicas; Services provide stable discovery; HPA scales from metrics; readiness/liveness probes support health management.
