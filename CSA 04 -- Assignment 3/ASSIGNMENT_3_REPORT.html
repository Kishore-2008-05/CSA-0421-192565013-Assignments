Q1 – Linking, Loading and Address Binding (6 marks)

Compile-time binding fixes addresses before execution; load-time binding relocates code when loaded; execution-time binding uses MMU translation. The linker resolves symbols and combines object files/libraries; the loader maps segments and shared libraries. Static linking embeds library code; dynamic linking shares libraries and permits compatible updates. Task01 demonstrates object linking, startup shared-library linking and dlopen/dlsym. Recommended design: versioned dynamic libraries for common encryption and runtime loading for optional algorithms, with ABI checks and safe error handling.

Q2 – Paging (8 marks)

Paging divides virtual memory into pages and physical memory into frames, removing external fragmentation while allowing internal waste. For 1024-byte pages, p=floor(A/1024), d=A mod 1024, and physical address=1024f+d. A 32-bit address with 4 KiB pages and 4-byte PTEs needs 4 MiB for a flat table; a 48-bit address with 8-byte PTEs would need 512 GiB, so multi-level tables are used. TLB EAT=h(t+m)+(1-h)(t+2m). Expected final-page waste for 100 processes is about 50 KiB (1 KiB pages), 200 KiB (4 KiB) and 100 MiB (2 MiB).

Q3 – Segmentation (6 marks)

A segment-table entry stores base and limit. Validate 0≤offset<limit; physical address=base+offset, otherwise raise a protection fault. Segmentation reflects logical code/data/stack regions but causes external fragmentation. Paging uses fixed frames and avoids external fragmentation; segmented paging combines logical regions with pages. Task03 tests valid/boundary/invalid accesses and includes a fragmentation simulation.

Q4 – Virtual Memory and Demand Paging (8 marks)

A page fault traps to the kernel, which validates the address, finds/creates the page, selects a frame, reads or zeros it, updates the PTE/TLB and restarts the instruction. With memory access 100 ns and fault service 8 ms, EAT=(1-p)100+p(8,000,000): approximately 8.10 μs at p=10^-3, 180 ns at 10^-5 and 108 ns at 10^-6. Working-set control helps prevent thrashing; copy-on-write shares pages after fork until a write.

Q5 – Page Replacement (8 marks)

FIFO evicts oldest, LRU least recently used, Optimal farthest future use and Clock approximates LRU with a reference bit. Supplied results for the given string: 3 frames FIFO 15, LRU 12, Optimal 9; 4 frames FIFO 10, LRU 8, Optimal 8. Belady string FIFO faults: 9 with 3 frames and 10 with 4. Clock/LRU-family approaches are preferred over FIFO for typical locality workloads.

Q6 – Disk Management (4 marks)

For six 4 TB disks: RAID0=24 TB/no tolerance; RAID1 as three mirror pairs=12 TB; RAID5=20 TB/one-disk tolerance; RAID6=16 TB/two-disk tolerance; RAID10=12 TB/at least one failure depending on mirror placement. RAID is not a backup. Choose RAID10 for performance or RAID6 for two-disk tolerance and retain off-host immutable backups.

Q7 – Memory Plan for 2 GB Edge Device (10 marks)

The control task needs deterministic deadlines and locked bounded memory; the 1.5 GB ML task should be capped and streamed; the logger should use bounded asynchronous buffers. Reserve RAM for kernel/drivers/DMA. Use PREEMPT_RT if real-time requirements demand it, pin the control thread, pre-fault/lock its memory and avoid blocking I/O. Only 0.5 GB remains after the ML task, so another 500 MB task cannot be admitted safely without streaming/offloading or more RAM. Linux mlock alone does not prove hard real-time behaviour.
