Task 1 – File-System Design Review (6 marks)

A flat directory for 12,000 students causes collisions and poor administration. Use /srv/student-data/<cohort>/<register-number>/{home,assignments,projects}, owner/group/mode, ACLs, quotas, snapshots, off-host backups and audit logs. Set private homes to 0700 and use dedicated groups for shared projects. Cloud sync is convenient but requires data-residency, account-lifecycle, retention and access-control review.

Task 2 – File Allocation for 32-Camera NVR (8 marks)

32 growing recordings need sequential writes/playback, time-based seeking and periodic deletion. A 4 GiB file with 4 KiB blocks has 1,048,576 blocks. Contiguous allocation computes offsets directly; linked allocation may traverse about 1,048,575 links for the final block; indexed/extents use a small number of index reads. A 4 TB decimal disk with 4 KiB blocks has about 976.6 million blocks; a bitmap needs about 116.4 MiB. Recommend extent-based ext4/XFS with fixed-duration segments and a time-to-file/offset index.

Task 3 – Modern File Systems (9 marks)

FAT32 has broad compatibility but a 4 GiB−1 byte maximum file size and no journal. NTFS offers metadata journaling; ext4 journaling; XFS large files and reflink CoW; Btrfs/ZFS CoW, checksums and snapshots; APFS CoW metadata and snapshots. ext4 data=journal journals data and metadata, data=ordered writes data before metadata commit, and data=writeback has weaker data ordering. Inspect using stat, df -i, ls -i and findmnt; only use tune2fs on a verified ext device.

Task 4 – Disk Scheduling (7 marks)

For cylinders 0–199, head 53, queue 98,183,37,122,14,124,65,67: FCFS=640; SSTF=236; SCAN toward 0 including endpoint=236; C-SCAN upward including wrap=382; LOOK=208; C-LOOK including circular jump=322. SSTF can starve distant requests; SCAN/C-SCAN offer sweep-based fairness; LOOK variants avoid unused end travel. Simulated wait results in the repository are model outputs, not physical disk measurements.

Task 5 – Distributed and Cloud Storage (7 marks)

NFS offers a shared namespace but can bottleneck at server/network; HDFS suits large sequential data; Ceph offers scale-out block/file/object services but needs expertise; cloud object storage is elastic but has request/egress costs and API semantics. Three replicas increase storage use roughly threefold and improve failure tolerance. Strong consistency provides ordered current data but adds coordination; eventual consistency may temporarily expose stale reads.

Task 6 – Video-Streaming Storage Design (13 marks)

For 200,000 students and videos of 300 MB–2 GB, use write-once/read-many architecture: durable object storage, CDN, metadata/time index, SSD/NVMe hot cache and HDD/object cold tier. Use 8–16 MiB streaming chunks as a tunable segment size, not an OS block size. 10,000 concurrent streams × 5 Mbit/s = 50 Gbit/s. 500 videos × 1 GB = 500 GB raw; two copies about 1 TB before metadata. Benchmark safely on test files and record cache hit ratio, throughput and p95 latency.
